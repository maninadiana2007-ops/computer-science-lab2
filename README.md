# Лабораторная работа №2

## Анализ веб-приложения и клиент-серверного взаимодействия

### 1. Исследуемая информационная система

Для выполнения лабораторной работы был выбран сервис Aviasales и пользовательский сценарий: поиск и покупка авиабилета.

Aviasales — это онлайн-сервис для поиска и сравнения авиабилетов. Пользователь работает через веб-интерфейс, который формирует запросы к API,
а сервер возвращает данные о найденных рейсах и обновляет состояние страницы.

В ходе исследования были выделены следующие основные компоненты:

1) браузер пользователя;

2) интерфейс сайта (frontend);

3) клиентский JavaScript, который управляет поиском и отображением результатов;

4) API-сервис, принимающий запросы от клиента;

5) backend, реализующий обработку данных;

6) хранилище данных, в котором хранятся рейсы, цены, заказы и бронирования;

7) внешние сервисы и ресурсы (Sentry, Mapbox, Google reCAPTCHA).

### 1.1. Сценарий исследования
Исследуемый сценарий:

1) Открытие главной страницы Aviasales.

2) Ввод параметров поиска (маршрут, даты, пассажиры).

3) Нажатие кнопки «Найти билеты».

4) Загрузка результатов поиска.

5) Применение фильтров и сортировки.

6) Выбор подходящего рейса.

7) Переход к оформлению и оплате билета.

## 3. Анализ HTTP-ответов
После выполнения запроса сервер возвращает HTTP-ответ, в котором содержатся статус-код, заголовки и тело ответа.
Для анализа были выбраны два запроса: один на загрузку главной страницы и один на получение результатов поиска.

### 3.1. Пример анализа ответа на запрос страницы

Для запроса загрузки главной страницы Aviasales был получен ответ со статусом 200 OK. 
Это указывает на успешную загрузку страницы, после чего браузер начал рендерить интерфейс.

Основные наблюдаемые заголовки:

- Content-Type: text/html — тип данных (HTML-страница);

- Cache-Control — политика кэширования содержимого;

- Date — дата и время ответа;

- Server — название серверного программного обеспечения (если видно).

Тело ответа представляло HTML-страницу, необходимую для инициализации интерфейса поиска.

## 6. Взаимодействие Frontend, API и Backend

Для выбранного пользовательского сценария важным является понимание цепочки событий от действия пользователя до визуального обновления интерфейса.

### 6.1. Последовательность событий

- Пользователь

- Интерфейс формы поиска

- JavaScript / frontend-логика

- HTTP-запрос к API

- Backend-сервис

- Обработка и сохранение данных

- HTTP-ответ

- Обновление интерфейса

- Пользователь видит список найденных рейсов

### 6.2. Конкретное действие

Рассмотрим действие: пользователь нажимает кнопку «Найти билеты» после ввода параметров поиска.

1) Пользователь взаимодействует с UI-элементом формы поиска (кнопка «Найти билеты»).

2) Frontend реагирует на действие и формирует HTTP-запрос.

3) Браузер отправляет запрос на API-адрес (POST /search/v3.2/results).

4) API принимает запрос и передаёт его на backend.

5) Backend обрабатывает данные: проверяет параметры поиска, обращается к базам данных авиакомпаний и агентств-партнёров, агрегирует цены и формирует список рейсов.

6) Сервер возвращает ответ со статусом успеха (JSON с данными о рейсах).

7) JavaScript frontend получает ответ и обновляет визуальную структуру страницы — вставляет список найденных рейсов.

8) Пользователь видит результаты поиска в рабочей области интерфейса.

### 6.3. Вывод по архитектуре

В результате исследования было подтверждено, что взаимодействие между клиентом и сервером происходит через HTTP. Браузер не хранит данные о рейсах локально;
он получает и отправляет данные через API, что позволяет приложению обновлять интерфейс динамически, без полной перезагрузки страницы.
