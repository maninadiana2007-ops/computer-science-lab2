# Анализ и моделирование данных предметной области

## 1. Описание предметной области

Предметная область: интернет-магазин.

Интернет-магазин занимается электронной торговлей и продажей товаров клиентам через веб-сайт.

Основные процессы:

-ведение каталога товаров;
-распределение товаров по категориям;
-формирование корзины пользователем;
-оформление и обработка заказов;
-хранение информации о клиентах (покупателях);
-сохранение истории оформленных заказов;
-учет товаров на складе.

Пользователи системы:
-клиенты интернет-магазина;
-администраторы магазина.

Основные задачи информационной системы:
-хранение информации о клиентах;
-хранение информации о товарах и их категориях;
-учет наличия товаров на складе;
-учет оформленных заказов;
-хранение перечня товаров в рамках конкретного заказа;
-хранение информации о статусах заказов;
-просмотр истории покупок клиента.


## 2. Объекты данных

В предметной области выделены следующие основные объекты данных.

### Клиент

Покупатель интернет-магазина, который оформляет заказы.


Необходимо хранить:
-идентификатор клиента;
-имя;
-адрес электронной почты;
-номер телефона;
-адрес доставки.

### Категория

Группа товаров, объединенных по общему признаку.

Необходимо хранить:
-идентификатор категории;
-название категории;
-описание.

### Товар

Конкретная позиция каталога, доступная для покупки.

Необходимо хранить:
-идентификатор товара;
-идентификатор категории;
-название;
-описание;
-цену;
-количество на складе.

### Заказ

Оформленная покупка клиента, содержащая один или несколько товаров.

Необходимо хранить:
-идентификатор заказа;
-идентификатор клиента;
-дату оформления;
-статус заказа;
-общую сумму.

### Позиция заказа

Конкретный товар в рамках оформленного заказа с указанием количества.

Необходимо хранить:
-идентификатор позиции;
-идентификатор заказа;
-идентификатор товара;
-количество единиц товара;
-цену на момент покупки.

## 4. Классификация данных

| Вычисляемые | общая сумма заказа | Значение может быть рассчитано как сумма стоимостей всех позиций заказа |

## 5. Связи между объектами

Между объектами предметной области были определены следующие связи.

### Клиент - Заказ

Тип связи: один ко многим (1:N).

Один клиент может оформить несколько заказов. Каждый заказ принадлежит одному клиенту.

### Категория - Товар

Тип связи: один ко многим (1:N).

Одна категория может содержать множество товаров. Каждый товар относится только к одной категории.

### Заказ - Товар

Тип связи: многие ко многим (M:N).

Один заказ может содержать несколько товаров. Один и тот же товар может присутствовать в разных заказах.

Для реализации связи многие ко многим используется промежуточная таблица «Позиция заказа», которая содержит идентификатор заказа, идентификатор товара, количество и цену на момент покупки.

## 6. Концептуальная модель данных

На схеме отражены следующие связи:

- Клиент 1:N Заказ;
- Категория 1:N Товар;
- Заказ 1:N Позиция заказа;
- Товар 1:N Позиция заказа.

Связь многие ко многим между заказом и товаром реализована с помощью промежуточной таблицы «Позиция заказа».

## 7. Оценка качества исходных данных

После построения концептуальной модели была выполнена оценка полноты и качества данных.

### Достаточно ли объектов выделено?

Да. Выделенные объекты описывают основные данные, необходимые для учета клиентов, каталога товаров, категорий, заказов и их позиций.

### Отсутствуют ли важные сущности?

Для рассматриваемой модели основных сущностей достаточно. При дальнейшем развитии системы могут быть добавлены склады, поставщики, платежи, отзывы и другие объекты.

### Все ли необходимые атрибуты определены?

Для построения концептуальной модели определены основные атрибуты каждого объекта. При реализации реальной информационной системы набор атрибутов может быть расширен.

### Имеются ли дублирующиеся данные?

Явного дублирования данных в модели нет. Информация о клиентах, товарах, категориях и заказах хранится в отдельных объектах и связывается между собой через внешние ключи.

### Достаточно ли информации для дальнейшего проектирования информационной системы?

Да. Выделены основные объекты, их атрибуты и связи. Полученная модель может использоваться как основа для дальнейшего проектирования базы данных.
