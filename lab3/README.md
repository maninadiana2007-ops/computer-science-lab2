# Анализ и моделирование данных предметной области

## 1. Описание предметной области

Предметная область: интернет-магазин.

Интернет-магазин занимается электронной торговлей и продажей товаров клиентам через веб-сайт.

Основные процессы:

-ведение каталога товаров;
-распределение товаров по категориям;
-формирование корзины пользователем;
-оформление и обработка заказов;
-хранение информации о клиентах (покупателях);
-сохранение истории оформленных заказов;
-учет товаров на складе.

Пользователи системы:
-клиенты интернет-магазина;
-администраторы магазина.

Основные задачи информационной системы:
-хранение информации о клиентах;
-хранение информации о товарах и их категориях;
-учет наличия товаров на складе;
-учет оформленных заказов;
-хранение перечня товаров в рамках конкретного заказа;
-хранение информации о статусах заказов;
-просмотр истории покупок клиента.


## 2. Объекты данных

В предметной области выделены следующие основные объекты данных.

### Клиент

Покупатель интернет-магазина, который оформляет заказы.


Необходимо хранить:
-идентификатор клиента;
-имя;
-адрес электронной почты;
-номер телефона;
-адрес доставки.

### Категория

Группа товаров, объединенных по общему признаку.

Необходимо хранить:
-идентификатор категории;
-название категории;
-описание.

### Товар

Конкретная позиция каталога, доступная для покупки.

Необходимо хранить:
-идентификатор товара;
-идентификатор категории;
-название;
-описание;
-цену;
-количество на складе.

### Заказ

Оформленная покупка клиента, содержащая один или несколько товаров.

Необходимо хранить:
-идентификатор заказа;
-идентификатор клиента;
-дату оформления;
-статус заказа;
-общую сумму.

### Позиция заказа

Конкретный товар в рамках оформленного заказа с указанием количества.

Необходимо хранить:
-идентификатор позиции;
-идентификатор заказа;
-идентификатор товара;
-количество единиц товара;
-цену на момент покупки.

## 3. Атрибуты объектов

Для каждого объекта были определены основные атрибуты и предполагаемые типы данных.

### Клиент

| Атрибут | Тип данных | Описание |
|---|---|---|
| id | Число | Уникальный идентификатор клиента |
| имя | Строка | Имя клиента |
| эл. почта|Строка|Адрес электронной почты клиента|
| телефон | Строка | Номер телефона клиента |
| адрес доставки | Строка | Адрес, по которому осуществляется доставка |

### Категория

| Атрибут | Тип данных | Описание |
|---|---|---|
| id | Число | Уникальный идентификатор категории |
| название | Строка | Название категории |
| описание | Строка | Текстовое описание категории |

### Товар

| Атрибут | Тип данных | Описание |
|---|---|---|
| id | Число | Уникальный идентификатор товара |
| category_id | Число | Идентификатор категории, к которой относится товар |
| название | Строка | Название товара |
| описание | Строка | Подробное описание товара |
| цена | Число | Стоимость одной единицы товара |
| остаток | Число | Количество товара на складе |

### Заказ

| Атрибут | Тип данных | Описание |
|---|---|---|
| id | Число | Уникальный идентификатор заказа |
| client_id | Число | Идентификатор клиента, оформившего заказ |
| дата | Дата | Дата и время оформления заказа |
| статус | Строка | Текущий статус заказа |
| сумма | Число | Общая стоимость заказа |

### Позиция заказа

| Атрибут | Тип данных | Описание |
|---|---|---|
| id | Число | Уникальный идентификатор позиции в заказе |
| order_id | Число | Идентификатор заказа |
| product_id | Число | Идентификатор товара |
| количество | Число | Количество единиц товара в заказе |
| цена при покупке | Число | Стоимость товара на момент оформления заказа |

## 4. Классификация данных

Выделенные данные можно классифицировать по их назначению и типу.

| Категория данных | Примеры | Назначение |
|---|---|---|
| Текстовые | имя клиента, email, телефон, адрес доставки, название категории, название товара, описание, статус заказа | Хранение текстовой информации об объектах |
| Числовые | идентификаторы, цена, остаток на складе, количество, сумма заказа | Хранение числовых значений |
| Даты и время | дата оформления заказа | Хранение информации о датах событий |
| Логические | отсутствуют в текущей модели | В текущей модели данные типа «да/нет» не используются |
| Справочные | категории товаров | Хранение перечня категорий для классификации каталога |
| Вычисляемые | общая сумма заказа | Значение может быть рассчитано как сумма стоимостей всех позиций заказа |
